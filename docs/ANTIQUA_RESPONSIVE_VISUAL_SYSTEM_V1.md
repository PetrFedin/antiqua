# ANTIQUA — Responsive Visual System v1

**Статус:** обязательный контракт публичного пользовательского интерфейса  
**Язык:** русский по умолчанию; полноценный английский только через EN  
**Цель:** единый музейно-редакционный визуальный язык на телефоне, планшете и мониторе.

## 1. Принцип

Произведение и исследовательский контекст всегда визуально важнее интерфейсной механики.

Публичная ANTIQUA не должна выглядеть как:
- CRM;
- BI-панель;
- административная система;
- типовой интернет-магазин.

Она должна сочетать:
- спокойствие музейной экспозиции;
- плотность хорошего каталога;
- удобство современного мобильного приложения;
- прозрачность исследовательской системы.

## 2. Базовые viewport

Обязательная проверка:
- телефон: 390×844;
- планшет: 834×1112;
- монитор: 1440×1000.

Дополнительно интерфейс не должен ломаться между контрольными ширинами.

## 3. Иерархия

Порядок визуального веса:
1. изображение произведения;
2. художник / название;
3. история и исследовательский контекст;
4. связанные произведения / коллекционный маршрут;
5. действия пользователя;
6. коммерческий статус — только если он существует;
7. техническая верификация — через раскрытие, а не на первом плане.

## 4. Типографика

Display serif используется для:
- названий произведений;
- имён художников;
- заголовков выставок и коллекций;
- крупных исследовательских заголовков.

UI sans-serif используется для:
- кнопок;
- фильтров;
- подписей;
- состояний;
- коротких фактов;
- вспомогательной навигации.

Запрещено превращать публичный экран в сетку из одинаковых мелких карточек с жирными KPI.

## 5. Изображения

- основное произведение имеет зарезервированное aspect-ratio;
- первый визуальный объект загружается приоритетно;
- вторичные изображения — lazy;
- изображения не меняют геометрию страницы после загрузки;
- на телефоне изображение может выходить к краям viewport;
- crop не должен скрывать важную часть произведения, если доступен contain/fit режим;
- thumbnails вторичны.

## 6. Сетки

### Телефон
- одна основная колонка;
- горизонтальные swipe-rails только для естественно сравнимых объектов;
- крупные touch-targets;
- минимум параллельных колонок;
- нижняя навигация не перекрывает действия.

### Планшет
- две содержательные колонки там, где они реально помогают;
- image + facts / research;
- wall может быть 2-column или асимметричной 6-column grid.

### Монитор
- максимум 12-column composition;
- свободное пространство важнее заполнения;
- допускается асимметрия размера произведений;
- public pages не должны превращаться в dense dashboard.

## 7. Touch targets

Практический минимум для основных действий:
- высота около 44 px и выше;
- достаточный интервал между соседними действиями;
- swipe rail не должен конфликтовать с вертикальным scroll;
- активная CTA не может менять положение из-за поздней загрузки блока.

## 8. Sticky

Допускаются только полезные sticky-поверхности:
- верхняя навигация;
- исследовательская навигация в длинном Досье;
- контекстные действия произведения.

Sticky запрещён, если:
- перекрывает CTA;
- создаёт несколько конкурирующих sticky-слоёв;
- закрывает значимую часть изображения на телефоне;
- вызывает pointer interception.

## 9. CLS / поздняя загрузка

Асинхронный блок обязан:
- получить reserved slot;
- показывать skeleton;
- заменить skeleton содержанием;
- не вставляться перед активной CTA после первого paint.

Целевой принцип:
`action position before async load ≈ action position after async load`.

## 10. Карточки

Карточка произведения:
- изображение;
- название;
- художник / период;
- объяснимый контекст;
- коммерческий статус только при наличии authority.

Не добавлять декоративные badge без информационной функции.

## 11. Цвет и поверхность

- нейтральная бумажная основа;
- высокий, но не резкий контраст;
- минимум цветового кодирования;
- состояния нельзя кодировать только цветом;
- красный/зелёный — не главный язык research confidence.

## 12. Движение

- спокойные переходы;
- лёгкий zoom изображения допустим на desktop hover;
- no mandatory motion;
- `prefers-reduced-motion` поддерживается;
- анимация не должна задерживать действие.

## 13. Публичные поверхности

Один визуальный язык обязателен для:
- Галереи;
- Досье;
- Художника;
- Коллекции;
- Выставки;
- связанных работ;
- Research / Provenance;
- Cultural Calendar.

Профессиональные кабинеты могут быть плотнее, но не должны влиять на публичную эстетику.

## 14. Responsive acceptance

На каждом контрольном viewport пользователь должен без увеличения браузера:
- открыть произведение;
- прочитать основные данные;
- перейти по исследованию;
- открыть художника;
- открыть связанную работу;
- сохранить работу;
- открыть коллекцию;
- вернуться назад;
- переключить RU / EN.

Не допускаются:
- горизонтальный scroll всей страницы;
- скрытая под fixed UI кнопка;
- текст за пределами контейнера;
- карточка шире viewport;
- layout jump при async mount;
- hover-only действие на touch-устройстве.

## 15. Метрики качества интерфейса

Проверяем:
- CLS;
- LCP основной artwork image;
- размер touch targets;
- число layout shifts после interactive;
- ошибки pointer interception;
- broken overflow;
- journey completion в browser E2E.

Эти показатели являются качеством интерфейса, а не бизнес-эффектом сами по себе.
