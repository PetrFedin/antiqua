# ANTIQUA — Политика локализации

**Статус:** ОБЯЗАТЕЛЬНЫЙ ПРОДУКТОВЫЙ КОНТРАКТ

## 1. Язык по умолчанию

ANTIQUA всегда открывается на русском языке, если пользователь ранее явно не выбрал английскую версию.

- русский — язык по умолчанию;
- русский — язык статического HTML до загрузки приложения;
- русский — fallback-интерфейс;
- язык браузера, операционной системы и география не переключают ANTIQUA на английский автоматически.

## 2. Английская версия

Английский включается только явным переключателем `EN`.

После переключения английская версия должна быть полноценной:

- вся навигация;
- заголовки;
- формы;
- состояния;
- подсказки;
- aria-подписи;
- подвал;
- пользовательские и профессиональные поверхности;
- Artwork Dossier;
- Investor / Pilot / Commercial Evidence поверхности.

Не допускается английская версия, где часть интерфейса остаётся на русском.

## 3. Запрет смешанного языка

В русской версии не допускаются видимые английские слова, если существует нормальный русский эквивалент.

Примеры:

- `Cash received` → `Получено денег`;
- `Gross contribution` → `Валовой вклад`;
- `Evidence reference` → `Ссылка на подтверждение`;
- `Collection Strategy` → `Стратегия коллекции`;
- `Market Context` → `Рыночный контекст`.

## 4. Допустимые исключения

Допускаются только общепринятые аббревиатуры и технические обозначения, когда перевод ухудшает точность:

- KPI;
- API — только в технических/операторских раскрытиях;
- SHA-256;
- HMAC;
- IIIF;
- URL;
- QR;
- валютные коды: EUR, USD, RUB и т. п.

Даже эти сокращения не должны доминировать в пользовательском интерфейсе.

## 5. Данные произведений

Для локализованных объектов:

`{ru: ..., en: ...}`

выбирается только значение текущего языка.

Запрещено:

`ru missing -> silently show en`

В русской версии отсутствующий русский перевод должен давать пустое/нейтральное состояние или явно оформленный статус отсутствия перевода, но не английский текст без предупреждения.

## 6. Внутренние коды

Внутренние значения вроде:

- `PAYMENT_RECEIVED`;
- `WRITTEN_ACCEPTANCE`;
- `DIRECT_COST_RECORDED`;
- `MEMORY_FALLBACK`;

могут существовать в API и данных, но в UI должны проходить через локализованный label.

## 7. Новые модули

Любой новый пользовательский модуль обязан:

1. использовать `copy(ru,en)` или эквивалент;
2. не содержать hardcoded английский user-facing label;
3. корректно переключаться без перезагрузки;
4. иметь русский статический/первичный вариант;
5. пройти browser localization contract.

## 8. Проверка

Автоматический тест:

`tests/browser/localization-default-ru.spec.mjs`

проверяет:

- отсутствие сохранённого языка → `ru`;
- `html[lang=ru]`;
- активный переключатель `РУ`;
- русские бренд-линии и footer;
- отсутствие английского fallback для `local({en: ...})`;
- явный switch `EN`;
- полноценное переключение shell на английский.

## 9. Artwork Experience

Новый Artwork Experience Layer следует этому же правилу.

Русская версия:

`Галерея → Произведение → История → Провенанс → Доказательства → Художник → Связанные работы → Коллекция`

Английская версия:

`Gallery → Artwork → Story → Provenance → Evidence → Artist → Related Works → Collection`

Никаких гибридов вида:

`Провенанс / Evidence Map / Related Works`

в одной русской пользовательской поверхности.

## 10. Приоритет

Если для новой функции существует только английский текст, функция не считается готовой к публичной русской версии до завершения локализации.
